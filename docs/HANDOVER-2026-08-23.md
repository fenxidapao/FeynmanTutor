## 1. 保留的建议（本窗口产出，未落地或半落地）

### 1.1 可检查记忆（画像带证据链）【未落地，推荐下一窗口做】
- 现状：`profile.weak_points` 只存 `["kp_id", ...]`，没有"为什么判定它是薄弱点"。
- 改法：存 `[{"kp_id": "...", "reason": "...", "evidence": ["ex_id1", "ex_id2"]}]`——诊断时把判定的依据（哪些题做错）一起存。
- 价值：面试"我的画像可审计"很硬；和 lumen 的"可审计 agent 决策"理念一致（REFERENCE 1.6）。

### 1.2 掌握门槛（Mastery gate）【未落地】
- 现状：`--learn` 流程"讲完就继续"，练习 3 次未通过只提示不卡点。
- 改法：练习 3 次未通过时把该 kp 标记 `blocked`，依赖它的后续知识点在规划/推荐中暂缓（knowledge-graph 已有 prerequisites，加判断即可）。

### 1.3 测验题 explanation 字段【已在 SQL 学习包落地，Python 包未补】
- SQL 学习包每题有 `explanation`（考什么概念），练习答错时可展示。
- 待办：给 Python 学习包 40 题补 explanation 字段（工作量约 1 小时，可让 LLM 生成后人工过一遍）。

### 1.4 报告页加"前后测对比柱状图"【未落地，UI 高 ROI】
- 在 Web 报告页加 Chart.js 柱状图：X 轴章节、Y 轴正确率，标注提升 pp。
- 价值：一眼看出"费曼组 ch2 提升 +40pp"——简历杀手锏的视觉化，对标 Bloom 的 2-Sigma 图。

### 1.5 热力图改"贡献热力图"风格【未落地】

- 价值：更有"学习时间感"，是 Bloom 的标志性 UI。**但优先级低于 1.4**（1.4 出数字，1.5 出观感）。

## 4. 遇到的难点和解决方法（新窗口别重复踩）

### 4.1 检索方案前提不成立（用户拍板解决）
- **问题**：PLAN 4.6 "调用侧 source 白名单" 不成立——实测 CourseRAG `/retrieve` 只接受 question/mode，sources 被静默忽略。
- **解决**：改为"检索 top-N 全量 → LLM 按内容相关性过滤 → notes 兜底"（rag.py）。零侵入 CourseRAG。

### 4.2 deepseek-v4-flash 是推理模型，max_tokens 预算坑（重大）
- **问题**：先输出 reasoning_content（思维链）再输出 content；max_tokens 是整个输出预算。给太小（如 20）→ 思维链吃光预算 → content 空 → 误判"空输出"重试仍失败。
- **解决（两层）**：
  1. 根治：model.py 新增 `ReasoningBudgetError`，`chat()` 遇预算不足**自动翻倍扩容重试**（上限 MAX_BUDGET=8000）
  2. 预防：各 Agent max_tokens 调大（诊断 1200/盲点 800/追问 500/提示 300/RAG 过滤 1600）
- **经验**：所有调用 max_tokens ≥ 200；health 检查也给了 200。

### 4.3 判题链路断点：mastery 永不更新（P3 发现）
- **问题**：`log_exercise` 只写 exercise_logs，从不更新 knowledge_points.mastery → 热力图全 0、规划"已掌握排最后"失效。
- **解决**：log_exercise 同步更新 mastery（滑动窗口最近 50 条正确率）+ status（mastered≥0.8/learning/reviewing）。

### 4.4 SQL 判题不能复用 Python 沙箱
- **解决**：sqlite3 内存库 + 统一预置 students/classes 表；查询题比结果集（列序敏感）、写操作题比表最终状态；多语句注入被 sqlite3 原生拒绝；结果集 200 行上限防笛卡尔积。

### 4.5 SM-2 首次答对语义
- **问题**：首次（interval=0）答对应给 1 天，代码给了 2 天（档位语义反了）。
- **解决**："用当前档位取间隔，答对后档位+1"（INTERVALS[0]=1 天起步）。

### 4.6 run_review_session 漏传 db_path
- **问题**：session 函数里 `db.log_exercise` 没传 db_path → 写默认库而非传入库。临时库测试才暴露。
- **经验**：函数签名有 db_path 时，session 内**所有** db 调用都要透传——这类 bug 只被多库测试抓住。

### 4.7 规划路径破坏依赖约束
- **问题**：薄弱点提前时，string.methods 跑到它的前置 string.basic 前面。
- **解决**：对薄弱点做**前置闭包**（递归收集所有前置），闭包整体按拓扑序提前。

### 4.8 Windows 环境坑（已解决，别再折腾）
- Bash 工具 120s 超时会杀长任务 → 长任务用 run_in_background
- python 子进程 stdout 是 \r\n → grader 比对前归一化
- uvicorn 不开 --reload 时改代码不生效 → 改 db.py 等后**必须重启服务**
- agent-browser daemon 频繁断连 → taskkill chrome/node 强杀重启
